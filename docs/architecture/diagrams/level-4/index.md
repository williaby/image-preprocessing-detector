# Level 4: Instance Registries

Level 4 is the fourth tier of the architecture documentation hierarchy. Where Levels 0–3 use
PlantUML workflow diagrams, Level 4 uses **Markdown tables** — "more table than workflow."

## Purpose

Level 4 documents the **per-dataset adapter instances** that are intentionally excluded from
Level 2 PUML diagrams (adding 81 adapter rows to a swimlane diagram destroys readability).
These 135 files are fully covered by Level 4 instance registries instead.

## `__l4_*` Header Convention

Python adapter files embed Level 4 metadata as module-level assignments immediately after the
module docstring, before imports:

```python
"""Parser for MyDataset — extracts layout annotations."""

# --- Level 4 registry metadata ---
__l4_category__    = "parser"              # REQUIRED: parser|provider|integrate-script|training-dataset
__l4_dataset__     = "my-dataset"          # REQUIRED: must match docs/datasets/canonical_names.json
__l4_workstream__  = "WS3"                 # REQUIRED: WS1|WS2|WS3
__l4_task__        = "layout"              # REQUIRED: controlled vocab (see below)
__l4_l2_file__     = "my_dataset_metadata.json"  # OPTIONAL: L2 metadata file name
__l4_integrate__   = "scripts/integrate_my_dataset_enrichments.py"  # OPTIONAL
__l4_status__      = "active"              # OPTIONAL: active|deprecated (default: active)
```

### Controlled Vocabulary for `__l4_task__`

| Value | Used by |
|-------|---------|
| `correction` | `parsers/correction/` adapters |
| `document` | `parsers/document/` adapters |
| `formula` | `parsers/formula/` adapters |
| `handwriting` | `parsers/handwriting/` adapters |
| `layout` | `parsers/layout/` adapters, docling_layout + yolo providers |
| `multilingual` | `parsers/multilingual/` adapters |
| `quality` | `parsers/quality/` adapters |
| `language` | language_detector provider |
| `iqa` | siglip + simulated providers |

### Naming Note

`__l4_*` uses the dunder-variable pattern consistent with SPDX headers elsewhere in this
codebase. While PEP 8 reserves double-underscore prefix/suffix names for Python internals,
collision with real Python dunder names is not a concern for these read-only metadata strings.
This choice is intentional — see multi-model consensus notes in the Level 4 design handoff.

## How to Add a New Dataset

When adding a new dataset adapter to this project:

1. **Add `__l4_*` header** to the new parser file (see template above)
2. **Add `__l4_*` header** to the new integrate script
3. **Add canonical name** to `docs/datasets/canonical_names.json`
4. **Regenerate registries**:

   ```bash
   python scripts/generate_level4_registries.py --category all
   python scripts/generate_level4_registries.py --check
   ```

5. **Verify** the new dataset appears in `data-preparation/annotation-parser-registry.md`

## Harvester Script

The registries are generated by `scripts/generate_level4_registries.py`:

```bash
# Generate all registries
python scripts/generate_level4_registries.py --category all

# Validate headers (CI mode — fails if orphaned files found)
python scripts/generate_level4_registries.py --check

# Scaffold a new adapter stub
python scripts/generate_level4_registries.py --scaffold \
    --category parser --dataset my-dataset --task layout --workstream WS3

# Emit raw harvest as JSON (debugging)
python scripts/generate_level4_registries.py --json

# Verbose output (shows skipped files)
python scripts/generate_level4_registries.py --check --verbose
```

## When to Regenerate

Regenerate after:

- Adding any new parser file to `src/.../annotation/parsers/**`
- Adding any new enrichment provider to `src/.../annotation/enrichment/providers/`
- Adding any new `scripts/integrate_*_enrichments.py`
- Adding `l4_*` front matter to a training dataset doc
