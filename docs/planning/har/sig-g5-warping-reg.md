## Section 7 — Cross-Head Consistency

### Head Interactions

| Related Head | Relationship | Consistency Requirement |
| --- | --- | --- |
| SIG-G5-2 (shadow_reg) | Both use doc3d source dataset; shadow and warping co-occur in bound book images | Different L2 fields (`shadow_severity` ≠ `warping_severity`). Co-occurrence in bound books is the key training challenge: a bound book page may have both high shadow_severity (gutter shadow) and high warping_severity (page curl). Both fields must be populated for co-occurring images. Risk: model learning shadow → warping correlation as spurious feature since both appear together in doc3d. Mitigation: include flat-document images with shadows AND warped images without shadows in training. |
| SIG-G5-1 (capture_cls) | ADF scanner (capture_method=scanner_adf) inherently causes warping from feed mechanism | OOD-3b images carry both capture_method=scanner_adf and warping_type=page_curl. Consistent labels across both heads for the shared OOD set are mandatory. A single annotation pass should populate both L2 fields. |
| SIG-G3-2 (skew_reg) | ADF curl causes apparent skew in addition to warping — skew_angle_degrees should be measured on ADF-curled images | OOD-3b labels include skew_angle_degrees. Consistent skew measurement methodology between warping_reg OOD and skew_reg training required to avoid confounding the two heads during evaluation. |

### Split Leakage Risk

**Level**: MEDIUM

doc3d (102,000 images) feeds warping training. If doc3d is also used for shadow_reg, global split registry must enforce that a doc3d image in the warping_reg training split is not in the shadow_reg test split. SmartDoc-QA is used in warping_reg only — no cross-head leakage risk from SmartDoc-QA. v3 warping views derive from synth-multiscript-v3 base images — global split registry must confirm v3 images in the warping views manifest are not in script_code training splits.

### Label Convention

`warping_severity = 0.0` means FLAT document (no warping). `warping_severity = 1.0` means extreme curl or perspective distortion where text lines are severely non-linear. The derivation formula from doc3d 3D mesh must map naturally to this scale — intermediate values (0.3 = light curl, 0.6 = moderate page curl) must be defined in the label_warping_severity.py docstring before any labels are generated. This convention must never use 0.0 to mean "unable to measure" — a separate measurement_failed flag must be used for that case.
