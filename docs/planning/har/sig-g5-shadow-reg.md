## Section 7 — Cross-Head Consistency

### Head Interactions

| Related Head | Relationship | Consistency Requirement |
| --- | --- | --- |
| SIG-G5-3 (warping_reg) | Both use doc3d source dataset; shadow and warping co-occur in bound book images | Labels must be independent: `physical_degradation.shadow_severity` and `physical_degradation.warping_severity` are different L2 fields. However, both must be populated for images where both distortions co-occur (e.g., bound book pages). Risk: model learning shadow → warping correlation as spurious feature, since both appear together in training data. Mitigation: ensure NONE-shadow images in training also include warped documents. |
| SIG-G1-1 through G1-6 (IQA) | Shadow causes localized blur in gradients and reduces local contrast | IQA heads (particularly blur_score and contrast_score) may develop spurious correlations with shadow_reg predictions. Shadow-free images must be present with various IQA degradation combinations. OOD-4a compound set specifically stresses this interaction. |
| SIG-G5-1 (capture_cls) | Shadow primarily occurs in camera-captured documents and scanner-lid-open scenarios | Consistent labels across capture_method and shadow_reg required for co-occurring cases: camera_smartphone images with shadows must have both fields populated. |

### Split Leakage Risk

**Level**: MEDIUM

doc3d (102,000 images) feeds shadow, warping, AND potentially IQA training. Global split registry (SHA256-keyed) required to prevent a doc3d image appearing in both the shadow_reg training split and the warping_reg test split (or vice versa). sd7k and wsrd are used only for shadow_reg training — leakage risk within this head is low, but cross-head leakage with any other dataset drawing from sd7k/wsrd must be confirmed absent.

### Label Convention

`shadow_severity = 0.0` means NO shadow present (not "unable to measure" or "measurement failed"). This convention must be consistent with the labeling script when created. Images where shadow is present but unmeasurable (e.g., binarized docs where gradient is lost) must use a sentinel value or separate boolean flag — the 0.0 convention must not be overloaded with "measurement failed." Convention must be documented in label_shadow_severity.py before any labels are generated.
