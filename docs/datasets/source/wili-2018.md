#### 7. Known Issues & Limitations

- **Text-Only Corpus**: ❌ Fundamental incompatibility with image preprocessing pipeline. Cannot assess visual quality, detect layout, or perform OCR on non-existent images.
- **No Script Codes**: ❌ Only provides ISO 639-3 language codes. Missing ISO 15924 script codes required for synthetic document generation (e.g., cannot distinguish Simplified vs Traditional Chinese).
- **Superseded by OpenLID-v2**: OpenLID-v2 provides superior integration with 201 languages + script codes + 116M samples. No reason to integrate second text corpus.
- **No Visual Features**: Cannot populate Layer 2 enrichment metadata (capture_method, quality, layout, degradations) as schema requires image input.
- **No Validation Split**: Only train/test splits provided. Would need to create custom validation split if used.
- **Paragraph Length Variance**: Wide range (140-40,600 characters) requires normalization for model training.
- **Wikipedia Bias**: Text sourced exclusively from Wikipedia, may not represent domain-specific language use (medical, legal, technical documents).
- **License Mismatch**: ODC Open Database License v1.0 on Zenodo vs Apache-2.0 in HuggingFace (minor documentation inconsistency).

**Blocked Status**: ❌ Cannot use for image-based training tasks (IQA, layout detection, OCR quality assessment).

1. Text-based language identification model training (low priority)
2. Script inference validation (mapping language → script)
3. Benchmark comparison vs OpenLID-v2 (research only)

#### 10. Dataset-Specific Notes

##### 10.1 Why This Dataset is Blocked

**Fundamental Incompatibility**: WiLI-2018 is a **text-only corpus** with NO image component.

**Prepare-Doc Requirements vs WiLI-2018 Capabilities**:

| Prepare-Doc Needs | WiLI-2018 Provides | Compatible? |
|-----------------|-------------------|-------------|
| Image preprocessing | Text paragraphs | ❌ No |
| IQA (quality assessment) | N/A | ❌ No images |
| Layout detection | N/A | ❌ No visual structure |
| Script identification (visual) | Language codes only | ❌ No script codes |
| OCR quality routing | N/A | ❌ No OCR output |
| Document metadata | Text metadata only | ⚠️ Partial (language only) |

**Conclusion**: Cannot be used for any image-based training tasks in Prepare-Doc pipeline.

##### 10.2 Comparison to OpenLID-v2 (Integrated Alternative)

**Why OpenLID-v2 is Preferred**:

1. ✅ **Script codes included** - ISO 15924 codes for 27+ scripts
2. ✅ **Already integrated** - TextCorpusManager implementation complete
3. ✅ **Massive scale** - 116M+ samples vs 235K
4. ✅ **Synthetic generation ready** - Direct pipeline integration
5. ✅ **BCP 47 tags** - Combines language + script + region

**WiLI-2018 Advantages** (not sufficient to overcome blockers):

- Broader language coverage (235 vs 201)
- Perfectly balanced classes (1,000 samples each)
- Wikipedia quality text

**Trade-off Analysis**: OpenLID-v2's script codes + scale + integration far outweigh WiLI-2018's slightly broader language coverage.
